# Targeted runtime probes

Start from one hypothesis and one observable HTTP, log or UI probe. Confirm checkout/process identity and actual endpoint registration. Missing connected runtime tools must be reported, not simulated.

Prefer an isolated app.inject test for mutation behavior. Live SQL writes require a known disposable target. Retain expected/actual evidence and stop blind retries after three failed attempts.

## Starter evidence

Read `apps/api/src/app.ts` in the application checkout. Use the captured starter snapshot recorded by the harness for copied examples; confirm changed source hashes before adapting them.
